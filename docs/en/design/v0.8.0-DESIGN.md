# v0.8.0 Design - collaboration_framing Redefinition and goal_locking_speed Signal Introduction

> This document is the technical design authority for v0.8.0. It defines the new four-dimensional structure of Collaboration Framing and the extraction and scoring logic for the first time-based collaboration efficiency metric (Goal Locking Speed).

---

## 1. Design Background and Core Goals

In earlier versions, the axis for starting collaboration was `intent_clarity` (task expression). That was reasonable in the Prompt era. In the **Agentic era**:
1. **Multi-turn clarification must not be penalized**: The primary skill is not a perfect first-turn Prompt but locking goals quickly through interaction (Goal Locking).
2. **An explicit "goal locking speed" signal is needed**: Measure user message turns from conversation start until AI's first effective modification (e.g. Write/Edit).
3. **Remove "external bonus" items from scoring**: `tool_leverage_bonus` and `workflow_maturity_bonus` added points outside the main score, distorting axis values. This version merges them fully into the `agentic_system` axis.

---

## 2. Architecture Evolution and Metric Redefinition

### 2.1 Axis Rename

Rename the first-layer capability axis from **`intent_clarity` (task expression)** to **`collaboration_framing` (Collaboration Framing)**.

### 2.2 Six-Axis Weight Adjustment

```
collaboration_framing  14%  (was intent_clarity, 15%)
execution_driving      25%  (was 24%)
implementation_depth   20%
delivery_closure       20%
adaptive_recovery      10%  (was 11%)
agentic_system         11%  (was 10%)
───────────────────────────
Total                  100%
```

The `total_score` formula removes external `tool_leverage_bonus` and `workflow_maturity_bonus` additions.

## 3. Collaboration Framing - New Four-Dimensional Sub-Items

```
collaboration_framing = _bounded_average(
    (direction_clarity_rate     * 100.0, 0.20),
    (context_grounding_rate     * 100.0, 0.18),
    (goal_locking_speed,                 0.28),
    (active_clarification_rate  * 100.0, 0.34)
)
```

| Sub-item | Weight | Source and Meaning |
| :--- | :--- | :--- |
| `direction_clarity_rate` | 0.20 | Former `constraint_prompt_rate` (direction and constraint clarity) |
| `context_grounding_rate` | 0.18 | Former `code_context_rate` (context injection rate) |
| `goal_locking_speed` | 0.28 | **New**: Speed of locking goals, boundaries, and deliverable path early; engineering sessions use `turns_until_first_file_write` as observable proxy; session scores averaged |
| `active_clarification_rate` | 0.34 | Active clarification rate (driven by `active_clarification`; from v0.6 patch boost to formal sub-item) |

### 3.1 `goal_locking_speed` Signal Definition and Scoring

For a single session, let $T = \text{turns\_until\_first\_file\_write}$ be user message turns before first effective write.
Linear interpolation:
$$
\text{locking\_score}(T) = \begin{cases}
100.0, & T \le 3 \\
0.0, & T \ge 10 \\
100.0 \times \frac{10 - T}{10 - 3}, & 3 < T < 10
\end{cases}
$$
In `aggregate`, arithmetic mean of $\text{locking\_score}(T)$ across valid sessions yields axis parameter `goal_locking_speed`.

### 3.2 Signal Extraction and Fallback

For readers with fine-grained Tool-level parsing (`claude_code`, `cline`, `cursor` jsonl, `gemini` jsonl):
- When traversing the conversation, user sends the $N$th human message.
- When AI's reply first calls a write/edit tool in `WRITE_TOOL_NAMES`, record $\text{turns\_until\_first\_file\_write} = N$.
- For sessions with no write tool detected (simple/historical sessions without fine tool stream), post-processing (`enrich_agentic_signals`) applies:
  - If `session.files_modified > 0`: fallback 3 (full score, 3-turn lock).
  - If `session.files_modified == 0`: fallback 10 (0 score, 10 turns without lock).

## 4. External Bonus Merged into `agentic_system` Axis

Remove `tool_leverage_bonus` and `workflow_maturity_bonus` from `total_score`; merge into `agentic_system` `_bounded_average`:

```python
agentic_system = _bounded_average(
    (skill_usage_session_rate * 100.0, 0.18),
    (workflow_fingerprint_session_rate * 100.0, 0.14),
    (structured_rate * 100.0, 0.12),
    (advanced_feature_ratio * 100.0, 0.12),
    (_soft_threshold(float(unique_skill_count), 2.0, 12.0, 100.0), 0.08),
    (_soft_threshold(float(workflow_reuse_depth), 1.0, 8.0, 100.0), 0.08),
    (asset_authoring_session_rate * 100.0, 0.05),
    (assetized_session_rate * 100.0, 0.04),
    (inventory_context, 0.03),
    (tool_bonus, 0.08),       # former tool_leverage_bonus micro-metrics
    (workflow_bonus, 0.08),   # former workflow_maturity_bonus micro-metrics
)
```

## 5. Backward Compatibility

For v0.6.0 and v0.7.0 snapshot data in v0.8.0 reports and compare pages:
1. **Deserialization compatibility**: In `SnapshotSource.from_dict` and `compare_snapshot_sources`, if historical snapshot has `intent_clarity` but lacks `collaboration_framing`, auto-rename and map to `collaboration_framing`.
2. **Snapshot cache isolation and re-parse**: `turns_until_first_file_write` introduces `CACHE_SCHEMA_VERSION` upgrade to `"1.4"`. Old cache is invalidated and re-parsed so all sessions get correct v0.8.0 temporal fields.

1. **i18n (`view_model_zh.yaml` / `view_model_en.yaml`)**:
   - Replace `intent_clarity` with `collaboration_framing`.

   - Radar and delta computation adapt automatically.
