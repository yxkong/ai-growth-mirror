# SDD: AI Growth Mirror v1.0.2 DDD Explainable Assessment and Readers

Chinese canonical version: [v1.0.2-DESIGN.md](../../design/v1.0.2-DESIGN.md)

This checked mirror summarizes the frozen contract. The Chinese document is the
only decision authority.

## Outcomes and boundaries

- DeepSeek Harness and ZCode root tasks enter the same analysis pipeline.
- A user sees score, evidence coverage, supporting and missing evidence, and a
  reviewable training action—not an unexplained verdict.
- Session Observation, Growth Assessment, and Learning Loop are separate bounded
  contexts. External formats enter through read-only anti-corruption layers.
- Unknown formats, unsupported schemas, policy-mismatched snapshots, and
  unprovable privacy boundaries fail closed. There is no legacy scoring formula
  or private transcript fallback.

## Canonical contracts

| Concern | Owner | Rule |
|---|---|---|
| Assessment semantics | `domain/growth/assessment_policy.py` | Versioned axis/component weights and thresholds |
| Assessment calculation | `domain/growth/assessment.py` | Pure observations-to-assessment calculation |
| Reader catalog | `infra/readers/catalog.py` | Adapter identity, CLI choices, and aliases |
| Report orchestration | `application/orchestrator.generate_report_artifacts` | One report pipeline |
| Analysis unit | Root task contract | Child-session evidence rolls up exactly once |

Missing evidence is unavailable, not perfect and not zero. Available components
and axes are renormalized; coverage and confidence stay visible. Raw token,
commit, tool, model, and subagent counts are context only. Outcomes,
verification, structured methods, and successful recovery are maturity evidence.

## Reader ACLs

DeepSeek Harness accepts session format v0 from raw JSONL or Zstandard frames,
validates the header and monotonic logical event sequence, ignores reasoning
content, and rolls descendants into the root session. ZCode opens `db.sqlite`
through a read-only SQLite URI, validates the required schema, reads only
session/message/part/usage relations, and never falls back to model-I/O rollout
files. Both expose structured diagnostics without transcript text.

## Verification

The release gate requires policy invariance tests, schema-negative and privacy
tests, raw/Zstd equivalence, SQLite read-only proof, root-task de-duplication,
bilingual/version checks, complete unit/eval regression, compile, lock check,
build, and diff hygiene. Unrun browser or release evidence remains explicitly
`NOT_RUN`.
