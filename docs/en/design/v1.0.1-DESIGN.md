## Design

### Unified outbound LLM privacy boundary

All LLM user prompts pass through one sanitizer in `infra/llm/execution.py`. It redacts structured secrets, PEM blocks, email addresses, home directories, and Windows/Unix absolute paths. Path fields are sanitized individually before rendering so paths containing spaces are removed in full. Upstream adapters still minimize row/message counts and lengths. Work-focus maintains a request-local mapping so repeated sessions from one project reuse the same anonymous label. User-derived text is enclosed by `UNTRUSTED_EVIDENCE_BEGIN/END`; system prompts state that instructions inside the evidence must not be executed. Provider error logs contain event codes and exception types, never request bodies or exception text that could echo them.

### OpenCode collection snapshot

One adapter collection builds an immutable index of global events, workspace models, source paths, and a stable SHA-256-derived revision over sorted relative names and canonical decoded JSON. Cache entries are stale when two positive revisions differ, so semantic content changes, additions, removals and timestamp rollback are covered without changing the stored field shape or Cache Schema. Parsing S sessions across W workspace files is `O(S+W)`. A malformed second-level JSON field is skipped with `AGM-OPENCODE-FIELD-SKIP`; it does not discard healthy fields. Unit tests use deterministic fixtures only.

### Status correctness and i18n

`CacheStore.iter_record_payloads()` reads local and per-machine layouts recursively. Status deduplicates by source machine, tool, and session, loads snapshot history from `report.output_dir`, and renders fixed copy from `status_zh.yaml` / `status_en.yaml`. `report.weekly_session_target` defaults to 8 and must be a positive integer. The design target is 100 ms for 1,000 fixture records, with a 500 ms CI threshold plus a single-pass structural assertion.

### Atomic persistence and snapshot layering

`infra/io/atomic.py` is the sole text/JSON atomic-write primitive: same-directory temporary file, flush and close, then `os.replace`, with cleanup on failure. POSIX additionally calls `fsync`; Windows skips it because runtime evidence showed an approximately 30-second delay per artifact while close+replace still preserves the required single-file atomicity. Cache, report, snapshot/comparison and index outputs use the primitive. Snapshot directories are staged completely, task-created staging directories are removed on failure, published once, and indexed last. If index publication fails, the implementation verifies and removes only the newly created unindexed snapshot directory before propagating the error.

Snapshot view assembly moves to `application/snapshot_service.py`; `infra/snapshots.py` retains only persistence, loading and payload-to-domain conversion. No infra-to-application allowlist remains, and no compatibility shell preserves the old owner.

### Calibration and CI

`tests/evals/fixtures/scoring_calibration_v1.json` holds synthetic, versioned cases. Tests exercise the sole `aggregate` scorer and assert invariants rather than prose snapshots: empty evidence, effective contracts, verified delivery, missing usage, and environmental recovery. CI runs locked uv installs, then invokes the synced platform `.venv` Python directly for unit + eval tests and compilation, and builds on Ubuntu/Windows with Python 3.12/3.13. This avoids an observed local Windows `uv run` wrapper delay while preserving lock fidelity. Actual hosted CI remains `release: NOT_RUN` until observed after push.

### Canonical owners and checked projections

The Chinese active contracts under `docs/design/` and `docs/config/` are the canonical documentation owners; English files are checked mirrors identified by `status: mirror` and `canonical_path`. Product version remains owned by `pyproject.toml`, Cache Schema by `domain/cache_schema.py`, and report orchestration by `application/orchestrator.generate_report_artifacts`. Runtime and archived snapshot sources share one business projection in `domain/snapshots/projection.py`; application code imports only public infra APIs. Status catalog keys are owned by `STATUS_LABEL_KEYS`. CI tests validate that workflow actions use 40-character commit pins without copying the current SHA into test code. No compatibility aliases or separate truth registry are introduced.

## Four-high, two-low, three-foundation projection

- High value/trust: every change traces to an audited fact and has negative/failure evidence.
- High efficiency/evolution: OpenCode becomes linear; i18n, atomic I/O, calibration and snapshot orchestration each have one extension point.
- Low context/change cost: no cache or CLI migration; module owners and validation commands are explicit.
- Maintainable/secure/observable: zero reverse dependency allowlists, fail-closed outbound privacy, atomic writes and stable safe diagnostics.

## Acceptance and limitations

AC-001 through AC-010 use targeted TDD first, followed by the locked full suite, build, lock and diff checks. Real LLM, real OpenCode data, browser behavior and hosted CI are reported as `NOT_RUN` unless they are actually observed.
