# v0.7.0 Design - Agentic Operating Maturity System Refactor

> This document is the technical design authority for v0.7.0 and records the strategic shift from "Prompt scorer" to "Agentic operating maturity assessment."

---

## 1. Problem Definition: Three Core Defects in the Current System

### 1.1 `intent_clarity` Measures "Prompt Era" Capability

`intent_clarity` raw score combines four sub-items:

```
intent_clarity_raw = constraint_prompt_rate × 0.28
                   + code_context_rate      × 0.24
                   + request_specificity    × 0.26
                   + (context_provision + scope_management)/2 × 0.22
```

**`constraint_prompt_rate` + `code_context_rate` total 52%**, essentially scoring "whether the first-turn Prompt is complete."

That fits Copilot-style users (AI = code completer): write requirements clearly, AI completes.
For **Agentic users**, the premise fails:

- Advanced mode is "give direction -> AI advances -> user corrects -> goal lock"; **multi-turn clarification is capability, not defect**
- `active_clarification_boost` (+8 cap) in v0.6.0 patches but the 52% base still favors first-turn completeness
- True Agentic quality ("can you frame direction quickly and let AI advance autonomously") has no independent place in the five-axis model

### 1.2 `agentic_system` Is a "Threshold Trigger," Not a "Continuous Contributor"

Current code:
```python
# agentic_system only used in L4/L5 gates
if agentic_system >= 88 and execution_driving >= 78 ...:
    score = max(score, 90)  # trigger L5
elif agentic_system >= 75 and execution_driving >= 70 ...:
    score = max(score, 75)  # trigger L4
```

Users building Skill, Workflow, MCP, Hook, Agent Asset cannot **continuously** contribute to total score. A user with a mature methodology but unstable delivery in one period may score low - the system does not recognize "methodology mature, execution fluctuated."

### 1.3 "Recovery Advancement" Misclassified as User Problem

Current logic: `user_interruptions >= 2` -> `off-track` friction -> `user-actionable`

But "continue / resume / retry" in Agentic scenarios is usually:
- Tool chain timeout
- Agent runtime context interruption
- Sandbox anomaly
- Command hang

This is **environmental friction**, not user capability. Misclassification as `user-actionable` wrongly lowers `adaptive_recovery`.

## 2. Version Goals

### v0.6.x (partially done; closed in this release)

Fix urgent bug: `environmental-recovery` misclassification.

### v0.7.0 (this document)

Promote `agentic_system` to the **sixth formal scoring axis**; adjust five-axis weights into a "three-layer maturity model."

### v0.8.0 (reserved)

Rename and redefine `intent_clarity` as `collaboration_framing` (Collaboration Framing); extend from "first-turn completeness" to "multi-turn collaboration startup quality."

### v2.0.0 (long-term)

Evolve from "single-session quality assessment" to "long-term AI work system maturity assessment."

## 3. Three-Layer Maturity Model

```
┌─────────────────────────────────────────────────────────┐
│  Layer 3: Can it become a reusable AI work system?       │
│  -> agentic_system axis (v0.7 promoted to formal axis) │
│  -> L4 -> L5 transition                                  │
├─────────────────────────────────────────────────────────┤
│  Layer 2: Can AI be driven to complete real work?        │
│  -> execution_driving + implementation_depth             │
│  -> delivery_closure + adaptive_recovery                 │
│  -> L2/L3 -> L4 transition (main battlefield)            │
├─────────────────────────────────────────────────────────┤
│  Layer 1: Can the human start collaboration?             │
│  -> intent_clarity (down-weighted; v0.8 -> collaboration_framing)│
│  -> L1 -> L2/L3 transition                             │
└─────────────────────────────────────────────────────────┘
```

## 5. v0.7.0 Technical Design

### 5.1 `agentic_system` Promoted to Formal Axis

**Existing `agentic_system` signals (already computed, reuse):**

```python
agentic_system = _bounded_average(
    (skill_usage_session_rate * 100.0,          0.22),
    (workflow_fingerprint_session_rate * 100.0,  0.16),
    (structured_rate * 100.0,                    0.14),
    (advanced_feature_ratio * 100.0,             0.14),
    (soft_threshold(unique_skill_count, 2, 12),  0.10),
    (soft_threshold(workflow_reuse_depth, 1, 8), 0.10),
    (asset_authoring_session_rate * 100.0,       0.06),
    (assetized_session_rate * 100.0,             0.05),
    (inventory_context,                          0.03),
)
```

**Change:** From threshold trigger to formal axis in `total_score` and radar rendering.

**New `total_score` formula:**

```python
total_score = (
    intent_clarity       * 0.15
    + execution_driving  * 0.24
    + implementation_depth * 0.20
    + delivery_closure   * 0.20
    + adaptive_recovery  * 0.11
    + agentic_system     * 0.10
    + tool_leverage_bonus        # max +4, gradually merge into agentic_system
    + workflow_maturity_bonus    # max +3, gradually merge into agentic_system
    + asset_maturity_bonus
    + consistency_modifier
)
```

**L4/L5 gate adjustment (agentic_system now in main score; gates can relax):**

```python
# L5 gate
if (session_count >= 15
    and agentic_system >= 80.0   # was 88
    and execution_driving >= 75.0
    and implementation_depth >= 68.0
    and delivery_closure >= 62.0
    and adaptive_recovery >= 52.0):
    score = max(score, 90)

# L4 gate
elif (session_count >= 15
    and agentic_system >= 65.0   # was 75
    and execution_driving >= 65.0
    and implementation_depth >= 60.0
    and delivery_closure >= 48.0):
    score = max(score, 75)
```

### 5.2 Fix `environmental-recovery` Misclassification

**New keyword patterns (heuristic extractor):**

```python
_RECOVERY_CONTINUATION_PATTERNS = frozenset({
    "继续", "恢复推进", "接着来", "接着做", "继续执行",
    "continue", "resume", "retry", "重试", "再跑一次",
    "你卡住了", "卡住了", "没反应", "超时了", "再试一次",
    "keep going", "go on", "proceed",
})
```

**Attribution rules:**

```python
# During friction classification, messages matching recovery continuation
# -> "environmental-recovery", no off-track, not user-actionable
if _is_recovery_continuation(user_message):
    friction_type = "environmental-recovery"
    attribution = "environmental"   # not in user_actionable_ratio
    # positive signal: record recovery_continuation_count
```

**`recovery_continuation_count` as positive signal in `adaptive_recovery` sub-items:**

```python
recovery_success_rate = successful_recoveries / max(recovery_continuation_count, 1)
```

### 5.3 Radar Upgraded to Six Axes

**Report layer changes:**
- `radar_axes` expands from 5 to 6, adding `agentic_system`
- Radar SVG polygon from pentagon to hexagon
- Tooltip shows `agentic_system` sub-dimension breakdown
- `gap_rankings` priority: `agentic_system` gaps rank above `intent_clarity` (more critical for L4->L5)

**i18n update (zh/en):**

```yaml
# view_model_zh.yaml
agentic_system:
  label: "Agentic 系统化"
  tooltip: "轴分 {score} · skill 使用率 {skill_usage_pct}% · workflow 结构化 {structured_pct}% · 资产创作 {asset_authoring_pct}%"
  gap_reason: "Agentic 系统化能力偏弱：尝试用 skill/workflow/MCP 沉淀可复用协作方法"
```

### 5.4 intent_clarity Weight Adjustment (v0.7.0 execution)

Only change weight coefficients; internal redefinition reserved for v0.8.0:

```python
# before
total_score = intent_clarity * 0.20 + execution_driving * 0.22 + ...

# after
total_score = intent_clarity * 0.15 + execution_driving * 0.24 + ...
```

## 6. v0.8.0 Reserved Design: `collaboration_framing`

> Reserved for v0.8.0; not implemented in v0.7.0 code.

### Rename

```
intent_clarity  ->  collaboration_framing
(task expression) -> (Collaboration Framing)
```

### Redefine Sub-Items ("first-turn completeness" -> "collaboration startup quality")

| Old sub-item | Weight | New sub-item | Weight | Change |
|---|---|---|---|---|
| `constraint_prompt_rate` | 0.28 | `direction_clarity_rate` | 0.20 | Direction not constraint completeness |
| `code_context_rate` | 0.24 | `context_grounding_rate` | 0.18 | Any turn with context counts |
| `request_specificity` | 0.26 | `goal_locking_speed` | 0.28 | Speed to lock goal in N turns (new signal) |
| `context+scope` avg | 0.22 | `active_clarification_rate` | 0.34 | Active clarification from patch to core |

### `goal_locking_speed` New Signal Definition

```python
# Goal locking speed: how fast user locks goals, boundaries, deliverable path early
# Engineering sessions use first file write as observable proxy
goal_locking_speed = soft_threshold(
    turns_until_first_file_write,
    lo=10,   # 10 turns before code -> 0
    hi=3,    # 3 turns -> full score
    max_pts=100,
    inverted=True,
)
```

## 7. Architecture Hard Constraints (inherited from v0.6.0 + new)

1. **Single-source weights**: Weight coefficients only in `scorer._compute_growth_level`; `ARCHITECTURE_PRINCIPLES.md` and report i18n derive from code comments; no parallel authority.

2. **No double-counting `agentic_system` signals**: After promotion, overlapping signals in `tool_leverage_bonus` and `workflow_maturity_bonus` gradually stripped; v0.7.0 coexists, v0.8.0 completes merge.

3. **`environmental-recovery` filter upfront**: Must complete at friction attribution stage; no second correction in scorer layer.

4. **Six-axis radar backward compatible**: Old five-axis snapshots show "—" for `agentic_system`; no error, no forced recompute.

5. **L1-L5 boundaries frozen**: Weight changes must not move level boundaries (0/38/56/75/90); boundary changes need separate proposal.

## 8. Report Content Closed-Loop Design

> **Closed-loop principle**: Every scoring change must have user-visible report presentation; backend-only metric changes are insufficient.

### 8.1 v0.7.0 Report Changes

| Report Area | Change | What Users See |
|---------|------|--------------|
| **Radar** | Pentagon -> hexagon | Sixth axis Agentic Systemization; skill/workflow/MCP usage distribution |
| **Axis tooltip** | agentic_system added | Hover: skill usage rate, workflow structure %, asset authoring rate |
| **gap_rankings** | Priority updated | `agentic_system` gaps before `intent_clarity` (more impact on L4->L5) |
| **adaptive_recovery note** | environmental-recovery excluded | "Continue/retry" no longer in user friction list |
| **Score card** | Weight transparency | Axis weight % updated (15/24/20/20/11/10) |

### 8.2 Diff vs v0.6.0 Report

```
v0.6.0 report                           v0.7.0 report
──────────────────────────────────    ──────────────────────────────────
Pentagon radar (5 axes)          ->     Hexagon radar (6 axes, + agentic_system)
intent_clarity 20%               ->     intent_clarity 15%
agentic_system not on radar      ->     agentic_system independent axis with tooltip
"Continue" may appear in friction ->    "Continue/retry" -> environmental, hidden
```

### 8.3 Backward-Compatible Rendering

Old v0.6 five-axis snapshots in v0.7 report:
- `agentic_system` shows `—` (no historical data), not 0
- Radar still hexagon; sixth axis labeled "no data yet"
- Period-over-period delta: new axis shows current value only on first period, no delta
