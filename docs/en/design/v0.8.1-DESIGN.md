# v0.8.1 Design - Collaboration Efficiency Fairness and Cold-Start Performance Optimization

> This document is the technical design authority for v0.8.1. It defines read-only/consultation session non-penalty logic, active clarification tolerance scoring, high-tier bonus sensitivity weight adjustment, and multi-threaded parallel session parsing.

---

## 1. Design Background and Core Goals

After v0.8.0 introduced time-based `goal_locking_speed` and merged bonuses into main axes, practice revealed:
1. **Read-only sessions wrongly penalized**: High-quality Q&A or design review sessions (no file writes) were fallback-scored as 10 turns without lock (0 points), heavily lowering Collaboration Framing.
2. **High-tier bonus sensitivity diluted**: After merging MCP usage, custom Skills, etc. into `agentic_system` (only 11% of total), advanced contributions barely moved total score.
3. **Active clarification vs fast lock conflict**: Multi-turn clarification scores high on active clarification but lengthens lock turns and penalizes `goal_locking_speed`.
4. **Performance bottleneck**: Cache Schema upgrade invalidated all history; cold-start serial parsing of large log caches was too slow.

This version aims for fair assessment and incentive for advanced human-AI collaboration, with multi-threaded cold-start acceleration at the orchestration layer.

---

## 2. Metric Redefinition and Weight Adjustment

### 2.1 Six-Axis Total Weight Adjustment

To strengthen incentive for high-leverage operations:
- **`agentic_system` (Agentic Systemization)** weight from 11% to **13%**.
- **`implementation_depth` (Implementation Depth)** from 20% to **19%**.
- **`delivery_closure` (Delivery Closure)** from 20% to **19%**.

```
collaboration_framing  14%
execution_driving      25%
implementation_depth   19%  (was 20%)
delivery_closure       19%  (was 20%)
adaptive_recovery      10%
agentic_system         13%  (was 11%)
───────────────────────────
Total                  100%
```

### 2.2 `agentic_system` Internal Sub-Item Weight Tuning

Raise substantive high-tier outcomes (tool bonus and workflow bonus); lower process-heavy weights:
- `tool_bonus` from 0.08 to **0.12**.
- `workflow_bonus` from 0.08 to **0.12**.
- `structured_rate` from 0.12 to **0.08**.
- `advanced_feature_ratio` from 0.12 to **0.08**.

## 3. Collaboration Framing Algorithm Upgrade

### 3.1 Read-Only Sessions Excluded from `goal_locking_speed` Average

In `heuristics.py`, for sessions with no write tool detected:
- If `session.files_modified > 0`: fallback 3 (full score; compatibility for legacy data missing fine turns).
- If `session.files_modified == 0`: `turns_until_first_file_write` **stays `None`** (no longer forced to 10).

In `scorer.py` aggregation:
```python
locking_speeds = [
    _goal_locking_speed_score(s.turns_until_first_file_write)
    for s in sessions
    if s.turns_until_first_file_write is not None
]
goal_locking_speed = sum(locking_speeds) / len(locking_speeds) if locking_speeds else 100.0
```
- Read-only review and architecture consultation sessions are skipped safely. If all sessions in the period are read-only, goal locking mean defaults to 100.0.

### 3.2 Active Clarification Tolerance Reward

If the user actively discusses constraints in turns 2/3 (triggering `active_clarification`):
- Turns used for goal locking scoring decrease by 1: $T = \max(1, T - 1)$.
- Multi-turn clarification sessions (e.g. write at turn 4) can still score 100 at the 3-turn lock standard, blending clarification quality and lock efficiency.

## 4. Write Tool Match Range Extension

Add emerging AI coding and Agent operation names to `WRITE_TOOL_NAMES` in `heuristics.py` so writes in Trae, Windsurf, Roo Code, etc. are not fallback-scored as zero writes due to naming mismatch:
- Added: `write_to_file`, `replace_file_content`, `multi_replace_file_content`, `edit_file_content`, `save_file`, `modify_file`, `update_file`, `change_file`.

---

## 5. Multi-Threaded Cold-Start Parallel Parsing

In `orchestrator.py`, for placeholder sessions missing cache on `ensure_parsed`:
```python
placeholder_sessions = [s for s in sessions if getattr(s, "_is_placeholder", False)]
if placeholder_sessions:
    from concurrent.futures import ThreadPoolExecutor
    with ThreadPoolExecutor(max_workers=8) as executor:
        list(executor.map(lambda s: s.ensure_parsed(cache_for_iter), placeholder_sessions))
```
- `ThreadPoolExecutor` parallelizes log / SQLite load, feature extraction, and cache write, greatly reducing cold-start time when schema upgrade invalidates all cache.

## 6. Backward Compatibility

- Upgrade `CACHE_SCHEMA_VERSION` to `"1.5"`; old cache auto-evicted.
- Historical snapshot axis score deltas realigned via updated `AXIS_WEIGHTS` in `comparison.py` for consistent compare.
