# v0.6.0 Design - Practice Feedback Loop

> Authoritative document for version goals, task breakdown, architecture constraints, and verification plan. Implementation follows this document.

---

## 1. Problem Definition

### 1.1 Training Suggestion "Black Hole"

Before v0.5.0, each report output 2 Action Contract training suggestions. After suggestions were given:

- The next report **could not tell** whether the user followed prior suggestions
- Users **felt no progress** because each report diagnosed only the current period
- The system could not distinguish "ignored suggestion" vs "executed but insufficient data"

**Root cause**: Report generation was stateless single-period behavior; snapshots archived but did not participate in current-period training judgment.

### 1.2 "Multi-Turn Interaction" Scoring Paradox

Current `intent_clarity` axis depends on:

| Sub-metric | Weight | Signal Source |
|--------|------|----------|
| `constraint_prompt_rate` | 28% | Constraints on first turn |
| `code_context_rate` | 24% | Code context included |
| `request_specificity` | 26% | Specific requirements |
| `context_provision` | 11% | Relevant background |
| `scope_management` | 11% | Clear scope closure |

**Problem**: When users complete a high-quality task through 2-3 turns (clarify goal -> add constraints -> confirm scope), `constraint_prompt_rate` penalizes missing first-turn constraints despite excellent delivery.

**Design decision**: v0.6.0 introduces "active clarification boost" - recognize "user asks -> AI fills context" as **explicit high-order collaboration intent**, not first-turn constraint absence penalty.

## 3. Scoring Fix: Active Clarification Signal (G-3)

### 3.1 What Is Active Clarification

When a session shows this pattern, mark **Active Clarification**:

```
User turn 1: Task description (may lack constraints)
AI turn 1: Questions or clarification suggestions
User turn 2: Explicit constraints / scope / acceptance (new context, not repeat)
-> session marked active_clarification = True
```

Rules (implemented: `domain/session/heuristics.detect_active_clarification`, shared by heuristic and LLM paths):
- `user_message_count >= 3`
- User turns 2-3 (`top_user_messages[1:3]`) contain constraint words (`CONSTRAINT_WORDS`: 不要 / must not / ensure / make sure / avoid / without, etc.)

> Note: Early draft required `request_specificity < 70` and `delivery_closure >= 60`; implementation converged on "turn count + later constraint words" for zero-LLM heuristic stability; confidence downgraded by sample size at aggregation layer.

### 3.2 Scoring Correction Rules

Correction in `domain/growth/scorer.py` `intent_clarity` via single-source `_intent_clarity_boost`:

```python
INTENT_CLARITY_BOOST_CAP = 8.0
_ACTIVE_CLARIFICATION_FULL_BOOST_RATE = 0.20

def _intent_clarity_boost(active_clarification_rate: float) -> float:
    if active_clarification_rate <= 0.0:
        return 0.0
    ramp = (active_clarification_rate / 0.20) * 8.0
    return round(min(8.0, ramp), 1)

intent_clarity = min(100.0, intent_clarity_raw + _intent_clarity_boost(rate))
```

**Rationale**:
- Linear ramp: +8 cap at 20% active clarification rate; proportional below (e.g. 10% -> +4)
- +8 cap prevents gaming via clarification alone
- `_intent_clarity_boost` single source for scoring and report transparency

### 3.3 Display Rules

- Report shows `active_clarification_rate`
- When boost > 0, `intent_clarity` axis tooltip adds: "includes +N active clarification boost"
- Boost logic shown transparently in stage assessment block

## 4. Action Contract Tracking (G-1)

### 4.1 Tracking Mechanism

Prior snapshot `sidecar.growth_plan` contains `action_contracts[]`, each with:
- `axis`: five-axis name (e.g. `intent_clarity`)
- `contract_type`: `rule | skill | workflow | template`
- `target_behavior`: expected behavior improvement

On current generate, read latest snapshot `action_contracts` from `infra/snapshots.py`; **outcome evaluation** in `application/growth_trajectory.py`:

```python
def evaluate_contract_outcomes(
    prev_contracts: list[ActionContract],
    current_profile: GrowthProfile,
    prev_profile: GrowthProfile,
) -> list[ContractOutcome]:
    ...
```

### 4.2 Outcome Judgment

| Result | Condition | Display |
|----------|------|------|
| `improved` | Target axis +5 points or more | Improved this period |
| `partial` | Target axis +1 to +4 | Partial improvement |
| `unchanged` | Target axis change < +/-3 | No clear change |
| `no_data` | First generate, no prior contract | Gray, "no prior data" |
| `schema_mismatch` | Prior used old axis names | Historical model incompatible |

**Confidence correction**:

When `prev_session_count < 8` or `current_session_count < 8`, all results `confidence = low`; report notes "insufficient sample, reference only."

### 4.3 New sidecar Schema Fields

Under `summary.json` `growth_trajectory`:

```json
{
  "contract_outcomes": [
    {
      "axis": "intent_clarity",
      "result": "improved",
      "delta_score": 8,
      "confidence": "medium",
      "prev_contract_text": "Add acceptance criteria on first turn each task",
      "evidence": ["constraint_prompt_rate up 12% this period"]
    }
  ]
}
```

## 5. Period-over-Period Delta Analysis (G-2)

### 5.1 Data Source

- Read local `ai-growth-mirror-archive/index.json` only; no network
- If archive entries = 0: hide entire delta section; show "no prior data"
- If >= 1: use latest as `prev_snapshot`

### 5.2 Delta Computation (new in `domain/snapshots/comparison.py`)

New pure function `compute_axis_delta()`:

```python
@dataclass
class AxisDelta:
    axis: str
    current_score: float
    prev_score: float
    delta: float
    trend: Literal["improving", "declining", "flat"]
    confidence: Literal["high", "medium", "low"]
```

Trend rules:
- `|delta| < 3`: `flat`
- `delta >= 3`: `improving`
- `delta <= -3`: `declining`
- Either period sample `< 8`: `confidence = low`

### 5.3 `human_intervention_rate` Trend

Track period-over-period change of `human_intervention_session_rate` in `TrendSummary`:

```python
@dataclass
class TrendSummary:
    ...
    intervention_rate_delta: float  # positive = worse (more human intervention)
    intervention_trend: Literal["improving", "declining", "flat"]
```

## 6. In-Report Period Cards (G-5)

### 6.1 Position and Trigger

- Position: inside `#section-growth-delta`, below radar
- Trigger: `growth_trajectory.available = True` (historical snapshot exists)
- No history: entire delta card area not rendered (no empty box)

### 6.2 SVG Trend Line

Pure SVG in `report.html.j2`:
- Width adapts (`viewBox="0 0 300 80"`)
- Max 10 points; if more, take latest 10
- Line color: improving=`var(--color-success)`, declining=`var(--color-error)`, flat=`var(--color-muted)`
- Point tooltip (reuse radar tooltip logic)

### 6.3 Change Arrow Cards

Per-axis mini card:
- Axis name + current score + delta (`+8` / `-3` / `±0`)
- Direction arrow (up/down/flat via SVG path, not Unicode)
- Confidence badge (gray when `low confidence`, copy "insufficient sample")

### 6.4 Action Contract Lookback

Below `#section-growth-plan`, new collapsible `<details>`:
- Title: "Prior Period Training Lookback"
- Content: `contract_outcomes` sorted `improved > partial > unchanged`
- No prior data: show "first generate, no lookback data" inside details, not hide entire block

## 7. CLI `status` Command (G-4)

### 7.1 Command Signature

```bash
ai-growth-mirror status [--config <path>]
```

### 7.2 Output Format (plain text, no LLM)

```
AI Growth Mirror - Current Status
──────────────────────────────────────
Last generate: 2026-06-05 14:32 (3 days ago)
Level: L3 · Collaboration Index: 72

Sample Progress
  New sessions this week: 12 / recommended minimum 15
  ████████░░ 80% -> 3 more effective sessions for new report

Weekly Practice Hints (from prior Action Contract)
  › Add acceptance criteria on first turn of next task
  › Try "@workspace" for code context before requesting

Run `ai-growth-mirror generate` for new report
```

### 7.3 Technical Constraints

- Response < 100ms: **forbid** full snapshot recompute
- Read only: `archive/index.json` (latest) + local cache manifest
- Sample count: sessions with `session_date` in last 7 days in local cache; no LLM extraction
- Weekly hints: read `latest_snapshot.growth_plan.action_contracts[0:2]` `target_behavior`
- No history: simplified "no report yet, run generate"

### 7.4 Implementation Location

```
cli.py            # new `status` subcommand
application/
  status_view.py  # StatusView DTO (new file)
infra/
  snapshots.py    # new load_latest_snapshot_meta() (read index.json only)
```

## 8. Architecture Constraints and Layering (inherit v0.5.x L5 guardrails)

### 8.1 Layer Ownership

| New Capability | Layer | Notes |
|----------|----------|------|
| `active_clarification` detection | `infra/extractors/heuristic.py` | Rule layer, no LLM |
| `active_clarification_rate` aggregation | `domain/growth/scorer.py` | Pure compute, no I/O |
| `intent_clarity_boost` correction | `domain/growth/scorer.py` | Same |
| `AxisDelta` / `ContractOutcome` DTO | `domain/snapshots/comparison.py` | Pure data + compute |
| `compute_axis_delta()` | `domain/snapshots/comparison.py` | Pure function |
| `evaluate_contract_outcomes()` | `application/growth_trajectory.py` | Assembly, reads profile |
| `load_latest_snapshot_meta()` | `infra/snapshots.py` | index.json only |
| `StatusView` DTO | `application/status_view.py` | New file |
| `status` subcommand | `cli.py` | Adapter layer |
| SVG trend + arrows | `assets/templates/report.html.j2` | Presentation only |
| Prior training lookback | `assets/templates/report.html.j2` | `<details>` collapse |

### 8.2 L5 Guardrails (inherit v0.5.x)

- **localStorage fallback**: theme read with `try-catch`; `file://` sandbox silently falls back to system preference
- **Defensive JSON parse**: `#report-data` parse all with `try-catch`; missing fields degrade locally
- **First-frame theme no flash**: sync script in `<head>` reads `localStorage` -> `data-theme` on `<html>`
- **Zero external deps**: new SVG lines forbid D3/Chart.js; `status` forbids network
- **`file://` double-click**: all new frontend logic tested under `file://`

### 8.3 Cache Schema Version

- Add `active_clarification` to `SessionRead` -> `SESSION_READ_SCHEMA_VERSION` rises to `"1.3"`
- Old cache (1.1 / 1.2) auto-invalidates, re-extract (no LLM cost in heuristic mode)

## 10. Verification Plan

### 10.1 Unit Tests

```bash
pytest tests/unit -q --tb=short -k "clarification or delta or contract or status"
```

Coverage:
- `test_active_clarification.py`: 5 positive/negative heuristic samples
- `test_scorer_intent_boost.py`: boost cap and threshold boundaries
- `test_axis_delta.py`: improving/declining/flat/low-confidence
- `test_contract_outcomes.py`: 5 outcomes + confidence correction
- `test_status_view.py`: StatusView with/without history

### 10.2 Integration Tests

```bash
pytest tests/ -q --tb=short -k "personal_growth_report or report_generation or cli"
```

- `test_personal_growth_report.py`: main report delta card render path
- `test_cli_generate.py`: `generate` does not crash on schema 1.3
- `test_cli_status.py` (new): `status` output with/without history

### 10.3 Manual Verification

- Generate with `--min-sessions 1`:
  - First generate: delta cards not rendered
  - Second generate: delta cards appear; SVG has points; arrows correct
  - `ai-growth-mirror status`: progress bar + practice hints; instant response
  - `file://` double-click: no CORS; SVG tooltip; `<details>` collapsible

## 11. Immutable Boundaries (must not break)

- `domain/` must not import `infra/application`
- `html_render.py` must not I/O, LLM, YAML load, or view assembly
- No second generate pipeline in `cli.py`
- `status` must not trigger `generate_report_artifacts`
- Period data must not call network; local archive only
- Report HTML must not import external JS/CSS (CDN, npm)
- New fields snake_case; enums in `domain/signals/taxonomy.py`
