# v1.0.0 Effective Task Contract and Agentic Report Calibration

## Goals

v1.0.0 corrects three distortions in the general Agentic report for highly rule-driven users. This version resets product version and cache schema from `1.0`; later iterations that do not change schema only bump patch versions.

1. Misclassify "read-code reconnaissance" as slow goal locking.
2. Miss engineering verification such as `build`, `compile`, `.ps1`, `.bat` as "no tests."
3. Treat existing task contracts in Skill / Rule / Workflow as "user did not write acceptance on first turn."

## Execution Plan

### P0: Model Completion

- `SessionRecord` adds task contract source, contract fulfillment, and pre-write read-only reconnaissance counts.
- Cache schema unified from `1.0` baseline to avoid mixing versions.

### P1: Reader Evidence Collection

- Cursor transcript records read / non-read tool counts before first write.
- Gemini / Antigravity reader supports UTF-8, UTF-8-SIG, GBK fallback.
- Gemini / Antigravity reader records pre-write reconnaissance and custom verification commands.

### P2: Heuristic and Scoring Calibration

- Extend verification command recognition: keyword/script-suffix matching instead of full command enumeration; tests, builds, compiles, and common Windows scripts enter Proof Loop.
- Add `effective_contract_rate`, unified across explicit Prompt, Skill/Rule, and Agent-derived contracts.
- Collaboration Framing axis uses Effective Task Contract to correct pure first-turn Prompt bias.
- Delivery Closure axis uses contract fulfillment rate to correct test-command-only bias.
- When all turns before first write are read-only reconnaissance, no ordinary delay penalty on goal locking speed.

### P3: Report and Training Suggestions

- `ai-growth-mirror.summary.json` adds stable `scorecard.task_contract` summary.
- Growth plan distinguishes "user did not write acceptance" vs "contract exists but Agent did not fulfill."
- For users with existing Skill / Rule contracts, suggestions focus on Agent contract restatement and closure compliance.
- "What you are doing" cross-session themes are synthesized by `work_focus/` LLM; on LLM absence or failure, fall back to rule guardrails; `goal_mix` / tools / languages stats remain rule-based rollups.
- Prompt Coach / growth_coach / prompt_lens remove fixed training templates and canned advice; personalized conclusions must be LLM-generated from packet evidence; i18n keeps labels and structure templates only.

### P4: Verification

- Heuristic coverage: build command recognition, Skill contract recognition, post-hoc correction recognition.
- Gemini / Antigravity coverage: GBK transcript, pre-write read-only reconnaissance, build verification.
- Report chain coverage: summary task contract output, read-only reconnaissance does not penalize goal locking.
- Version consistency coverage: pyproject, `__init__`, README badge, uv.lock.

## Version Strategy

- `CACHE_SCHEMA_VERSION=1.0` maps to product line `v1.0.x`.
- When schema is unchanged, only patch iteration is allowed, e.g. `v1.0.1`, `v1.0.2`.
- When schema upgrades, product line upgrades in sync, e.g. `CACHE_SCHEMA_VERSION=1.1` -> `v1.1.0`.
- Every version bump must update `pyproject.toml`, `ai_growth_mirror/__init__.py`, `uv.lock`, `README.md`, `docs/design/README.md`, `docs/design/PRODUCT_ROADMAP.md`, and the current design doc.

## PowerShell Command Rules

- On Windows, checkpoint, version read, and test commands must use pure `pwsh` form; no Bash heredoc.
- When `$` variables are needed inside `pwsh -Command` strings, escape with backtick, e.g. `` `$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD ``.
- Prefer temporary `.ps1` or Python scripts for complex commands; do not pack nested `$variables`, pipes, and complex regex into one double-quoted command.
- For multiple fixed-string keywords, prefer `rg --fixed-strings -e ...` to avoid `|` being misread by shell or regex layers.

## Acceptance Criteria

- v1.0.0 can explain "why a user may have no hand-written first-turn acceptance but still have an Effective Task Contract."
- Report shows task contract source distribution and fulfillment rate.
- Antigravity / Gemini build verification and Windows scripts are no longer missed.
- Read-only reconnaissance no longer lowers goal locking speed.
- Focused unit tests all pass.
