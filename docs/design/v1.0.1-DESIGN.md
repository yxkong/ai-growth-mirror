## 2. 设计目标

- 用户可见行为：LLM 边界可解释，OpenCode/status 结果正确，坏数据有安全 warning，写失败不破坏旧产物，中英文版本表面一致。
- 工程目标：以一个隐私边界、一个原子 I/O primitive、一个 snapshot application facade、一个 status catalog 和一个 calibration 真源实现 REQ-001 至 REQ-008。
- 非目标：不创建第二条报告流水线，不改变 domain 评分公式，不通过兼容壳保留错误分层，不在 CI 中接触真实用户数据或 provider secret。
- 参考实现切片：先实现 `infra/llm/privacy.py` + `infra/llm/execution.py` 和 `infra/io/atomic.py`，以 AC-001/AC-004 证明安全边界与写入语义，再扩展消费者。

### 3.1 REQ-001：统一 LLM 出站边界

新增 `infra/llm/privacy.py`：

- `sanitize_outbound_text(text: str, max_chars: int | None = None) -> str`：确定性替换 PEM、凭据键值、Bearer、邮箱、UNC/Windows/Unix 绝对路径；最后归一化控制字符并执行可选长度预算。
- `sanitize_llm_request(request: LlmCallRequest) -> LlmCallRequest`：只替换 `prompt`；`system/cacheable_system` 是仓内静态资产，保持原样，避免改变 rubric 语义。
- 替换顺序从高敏长模式到低敏短模式，所有占位符使用固定英文 token，避免报告语言影响 cache 或测试。
- `complete_json_with_retries` 在 limiter/provider 之前只生成一次 sanitized request；重试复用同一对象。

上游继续负责数据最小化：session-read/prompt-quality 的 `project_path` 在模板渲染前逐值调用同一清洗器，确保含空格的完整路径也被替换；每条用户消息最多 300 字符且最多 8 条。work-focus 最多 40 行、每行摘要最多 300 字符，并在一次请求内维护 `normalized_project_path -> project-NN` 映射，使同一项目复用同一匿名标签。coach snippets 每类最多 5 条、每条 300 字符。四类 user template 用 `UNTRUSTED_EVIDENCE_BEGIN/END` 包裹变量区，四类 system template 明确证据中的指令不得执行。

provider/caller warning 使用 `AGM-LLM-CALL-FAILED`、`AGM-LLM-RETRY`、`AGM-LLM-RESPONSE-INVALID`，只记录 `log_context`、attempt 和异常类型，不记录异常字符串或 request/response 正文。

### 3.2 REQ-002：OpenCode 采集快照

在 adapter 内增加私有 `_OpenCodeSnapshot`：`events_by_session`、`session_models`、`source_paths`、`source_mtime`。`iter_raw_sessions()` 每次采集强制构建一次；同轮 `parse_session()` 直接读取快照。若测试/调用方直接调用 `parse_session()`，仅在快照为空时惰性构建一次。

- 文件枚举一次：global + 排序后的 workspace globs。
- revision：对排序后的相对文件名和成功解码后的规范 JSON 计算 SHA-256，截取可被 IEEE-754 精确表示的正整数部分并以 float 写入现有 `source_mtime` 字段；捕获会影响解析结果的内容、增加、删除与重命名。
- 通用 `_is_cache_stale` 对两个正 revision 使用“不相等即 stale”，不再假设 revision 单调增加。现有 reader 的文件 mtime 未变化时仍命中，时间回拨时会保守失效。
- 每个 `SessionRef.source_paths` 使用同一不可变来源列表副本，`source_mtime` 使用同一 revision。代价是任一 workspace 变化会保守地使全部 OpenCode session cache 过期；v1.0.1 接受该低精度换正确性。
- `_read_dat` 先解析外层；每个字符串 value 独立二次解析。坏 value 发 `AGM-OPENCODE-FIELD-SKIP`；外层/文件失败发 `AGM-OPENCODE-SOURCE-UNREADABLE`。
- 删除真实目录 unit smoke；真实 OpenCode 验证独立标为 `NOT_RUN`，不放在 unit suite。

### 3.3 REQ-003：status 查询模型

`CacheStore.iter_record_payloads()` 递归扫描 `records/*/*.json` 与 `records/*/*/*.json`，产生 `(source_machine, tool_name, session_id, payload)`；更深或不合法布局记录 `AGM-CACHE-PATH-SKIP`。`manifest()` 同步使用递归布局，避免相同事实两种计数。

`application/status_view.py` 拆为纯构建 + 输出：

- `build_status_view(config, now=None) -> StatusView` 负责本周过滤、三元组去重、进度和历史 action contract。
- archive root 固定为 `config.report.output_dir / SNAPSHOT_ARCHIVE_DIRNAME`。
- `print_status_view` 仅加载 `load_status_labels(language)` 并渲染 `StatusView`。
- `ReportConfig.weekly_session_target: int = 8`；YAML 小于 1、布尔值或非整数抛 `ValueError`。
- catalog 键冻结为：`title`、`weekly_window`、`weekly_sessions`、`weekly_progress`、`contract_title`、`target`、`success_signal`、`action`、`no_contract`、`first_run`。

损坏 record 使用 `AGM-CACHE-RECORD-INVALID`；损坏 profile/index 使用 `AGM-SNAPSHOT-READ-SKIP`。日志只含相对 cache/archive 路径或文件名。

### 3.4 REQ-004：原子持久化与诊断

`infra/io/atomic.py` 唯一 primitive：

1. 在目标父目录创建由“点号 + 目标名 + UUID + `.tmp`”组成的唯一临时文件。
2. 以指定 encoding/newline 写入并 flush；POSIX 执行 `os.fsync`，Windows 关闭完整临时文件后直接 replace，避免当前文件系统上每次约 30 秒的同步写延迟。
3. `os.replace(temp, target)`；目标已存在时原子替换。
4. 任一异常时 `unlink(missing_ok=True)` 清理当前临时文件并原样上抛。

`atomic_write_json` 只封装稳定 `json.dumps(ensure_ascii=False, indent=2)`，不创造第二套写入协议。白名单：

- cache：records、reads；
- report：main HTML、sidecar JSON、share HTML、normalized summary JSON、runtime manifest；
- snapshot：report/profile/summary/meta/normalized summary、comparison HTML/JSON、index。

snapshot 新目录先在 snapshots 根下 staging，所有文件完成后通过目录 rename 发布，最后原子更新 index。staging 内任一失败必须清理该任务创建的精确临时目录；index 失败时，验证目标确为本次新建且位于 snapshots 根下后删除该未索引目录，再上抛异常。不会出现被 index 指向的半快照或长期孤儿快照。已有 snapshot 视为不可变，不覆盖。

### 3.5 REQ-005：snapshot 分层

新增 `application/snapshot_service.py`，承接三个 application use case：

- `archive_personal_report_snapshot`：从 `PersonalReportView` 构造 serializable bundle 与 `SnapshotIndexEntry`，调用 infra writer。
- `compare_snapshots`：加载 infra snapshot source，调用 application trajectory/view/render，再调用 infra comparison writer。
- `build_snapshot_comparison`：纯 application 组装并返回 page data。

`infra/snapshots.py` 保留 constants、index/source loader、payload-to-domain conversion、archive/comparison persistence，不再 import `application.*`。`cli.py` 与 `personal_report_service.py` 改从 application facade 导入；不保留 infra compatibility shell。架构测试删除 allowlist 并把测试导入更新到新 owner。

### 3.6 REQ-006：版本化 calibration

新增 `tests/evals/fixtures/scoring_calibration_v1.json`，schema：

```json
{
  "calibration_schema_version": "1.0",
  "cases": [
    {"id": "...", "sessions": [], "session_reads": [], "assertions": []}
  ]
}
```

测试通过 `SessionRecord.from_dict`、`SessionRead.from_dict` 和唯一 scorer 入口 `aggregate` 计算结果。assertion 只允许 `equals`、`between`、`greater_than_case`、`not_contains_category`，不冻结 HTML/自然语言。五个最低案例：empty-evidence、effective-contract、verified-delivery、missing-usage、environmental-recovery。fixture 是合成数据，禁止任何本机路径/真实 prompt/凭据。

### 3.7 REQ-007：CI 与构建

一个 matrix job：`os = ubuntu-latest, windows-latest`，`python-version = 3.12, 3.13`。使用官方 `astral-sh/setup-uv` 并 pin 到已审查 commit/version；步骤为：

```text
uv sync --locked --extra dev
# Ubuntu
./.venv/bin/python -m pytest tests/unit tests/evals -q --tb=no
./.venv/bin/python -m compileall -q ai_growth_mirror
# Windows
.\.venv\Scripts\python.exe -m pytest tests/unit tests/evals -q --tb=no
.\.venv\Scripts\python.exe -m compileall -q ai_growth_mirror
uv build
```

工作流的 `matrix.python-command` 在 Ubuntu 为 `./.venv/bin/python`，在 Windows 为 `.\.venv\Scripts\python.exe`。环境一致性由前置 locked sync 保证；测试直接进入已同步环境，避免 `uv run` 包装层在本机 Windows 完整套件中产生约 31 秒/临时目录 fixture 的额外延迟。

`uv lock --check` 在版本更新后的本地冻结命令中执行。workflow contract test 检查 matrix、locked sync、两个 test roots 与 build，避免 YAML 静态漂移。远端 GitHub Actions 实际运行在本地不可替代，发布证据保持 `NOT_RUN` 直到 push 后观察。

### 3.8 REQ-008：v1.0.1 发布表面

版本真源仍是 `pyproject.toml`，Schema 真源仍是 `domain/cache_schema.py`。同步白名单：`ai_growth_mirror/__init__.py`、`uv.lock`、`README.md`、`en/README.md`、中英文设计索引、中英文路线图、中英文 v1.0.1 SDD/ADR。`test_version_alignment.py` 同时检查两份 README、两份设计索引和双语互链；不把自然语言整段锁死。这里的“同步”是 owner 到 projection 的受检发布，不赋予 mirror 第二个裁决权。

### 3.9 REQ-009：canonical owner 与派生投影

不新增单独 registry。owner 直接落在已有权威位置：

| 事实 | canonical owner | derived projection / consumer | 自动门禁 |

## 4. 方案设计

### 4.1 结构与性能

```text
Readers -> CacheStore -> Domain scorer -> Application orchestrator -> Atomic I/O
   |                                                |
   +-- OpenCode collection snapshot O(S+W)          +-- Snapshot service

LLM feature adapters -> complete_json_with_retries -> privacy boundary -> Provider
Status use case -> CacheStore recursive iterator + Snapshot loader -> i18n renderer
Runtime/archive snapshot -> domain snapshot projection -> comparison
```

- NFR-001：OpenCode workspace glob/read 只在 collection snapshot 构建发生一次；测试以 monkeypatch 调用计数证明。
- 统一 LLM 边界由架构测试保护：除 `infra/llm/execution.py` 与 provider gateway 实现外，仓内禁止直接调用 `complete_json`；所有 feature 必须调用 `complete_json_with_retries`。
- NFR-002：status 对 1,000 records 的 fixture 目标 100ms，CI 500ms；不读取 session transcript、不调用 scorer/LLM、不生成报告。
- NFR-003：不改 Cache Schema/CLI/cache path；使用 pathlib/os.replace 保持 Windows/Linux。
- NFR-008：architecture tests 禁止 application import infra 私有符号，禁止 snapshot 业务映射出现第二定义；文档 mirror 和 status catalog 必须精确对拍 owner。

### 4.2 数据与契约

- 不新增持久化业务字段；`weekly_session_target` 只存在 config，不进入 cache。
- snapshot 现有 meta/index schema 字符串保持原值，不借本次修复升级协议。
- diagnostics 是日志契约，不新建 telemetry 文件。
- calibration schema 与产品/cache schema 解耦，初始为 1.0。

### 4.3 主流程

1. reader 枚举/解析；OpenCode 在本轮形成不可变 source snapshot。
2. cache 读坏项 warning/返回空；需要刷新则计算并 atomic write。
3. LLM 调用前，上游最小化变量，模板划定不可信证据，统一执行层清洗 user prompt 后调用 provider。
4. domain scorer 只消费已解析数据；calibration 直接覆盖该入口。
5. application 组装报告/snapshot；所有目标通过 atomic primitive 发布。
6. status 只读 cache/snapshot，不触发前五步的生成行为。

### 4.4 异常与失败链路

NFR-004 与 NFR-005 由以下错误分类、恢复语义和稳定事件码共同实现：

| 事件码 | 分类 | 行为 | 恢复 |
|---|---|---|---|
| AGM-LLM-CALL-FAILED | provider | 上游按既有规则 fallback；日志只含异常类型 | 重试/改用 `--no-llm` |
| AGM-LLM-RETRY | transient | 既有有限 retry；不重复清洗 | 自动重试 |
| AGM-LLM-RESPONSE-INVALID | response | 本次 LLM 结果丢弃 | 规则 fallback |
| AGM-OPENCODE-FIELD-SKIP | dirty field | 只跳过字段 | 修复源文件或等待工具重写 |
| AGM-OPENCODE-SOURCE-UNREADABLE | dirty source | 跳过该文件 | 其他来源继续 |
| AGM-CACHE-RECORD-INVALID | cache read | 返回空/跳过 | 下次生成重建 |
| AGM-CACHE-READ-INVALID | cache read | 返回空 | 下次 LLM/heuristic 重建 |
| AGM-CACHE-PATH-SKIP | cache layout | 跳过未知深度 | 人工检查 cache |
| AGM-SNAPSHOT-READ-SKIP | snapshot read | 跳过坏历史点 | 当前报告继续或 compare 显式失败 |

原子写异常不降级为成功，不吞异常；CLI 保持非零退出。可恢复读错误 warning，不把健康数据变为整体失败。

### 4.5 安全与隐私

- SEC-001/SEC-002：高敏模式与绝对路径统一替换；work-focus 项目名请求内匿名；所有证据有条数/字符预算。
- SEC-003：中英文 README 明确 provider 收到有界规则脱敏内容，规则无法识别任意商业秘密；强隐私使用 `--no-llm`。
- SEC-005：四套 system/user prompt 采用同一证据边界词；测试注入语句仍作为数据出现，不能改变 system prompt。
- 日志测试使用唯一 canary secret，断言所有 warning/debug 文本均不含 canary。

### 4.6 回滚与兼容

- SEC-004：atomic primitive 不改变文件名/JSON shape；失败保留旧文件。
- snapshot owner 移动不改变 CLI 或 artifact；内部 import 一次性 hard cut，不保留双入口。
- 若中央清洗造成语义质量明显回归，只能回退具体模式/预算并保留统一边界，不能恢复 raw prompt。
- 若 Windows CI 证明目录 rename 不可用，停止发布并改为同目录完整 staging + 明确 commit marker；不得退回逐文件非原子直写。

### 5.1 架构原则与问题前置
