# v0.8.1 详细设计 — 协作效能公允度升级与冷启动性能优化

> 本文档是 v0.8.1 的技术设计权威文档，定义了只读/咨询会话免扣分逻辑、主动澄清容错打分奖励算法、高阶 Bonus 敏感度权重调整，以及多线程并行会话解析的技术设计。

---

## 一、设计背景与核心目标

在 v0.8.0 引入基于时序的协作效率指标 `goal_locking_speed` (目标锁定速度) 及将 Bonus 融入主轴后，我们在实践中发现以下问题：
1. **只读会话误伤扣分**：对技术咨询或设计排查的高质量问答会话（没有文件写入），原 Fallback 逻辑直接视作 10 轮未锁定（0分），极大地拉低了用户的协作框定得分。
2. **高阶 Bonus 敏感度稀释**：将 MCP 使用、自定义 Skill 等外挂加分融入 `agentic_system` 轴后，受该轴在总分中仅 11% 权重的制约，用户做出的高阶贡献对总分的撬动作用非常微弱，极难获得激励正反馈。
3. **“主动澄清”与“快速锁定”冲突**：多轮澄清可以获得 active clarification 高分，但会让锁定轮数变长而被 goal_locking_speed 扣分。
4. **性能瓶颈**：Cache Schema 的升级废弃了所有历史缓存，导致冷启动扫描时需逐个串行解析大 logs 缓存，耗时过长。

本版旨在公允评估和激励高阶人机协作技巧，并从架构编排层完成多线程冷启动并行加速。

## 二、指标重定义与权重调整

### 2.1 六轴总权重调整

为了配合增强高杠杆/高阶操作的激励：
- 将 **`agentic_system` (Agentic系统化)** 权重从 11% 提升至 **13%**。
- 将 **`implementation_depth` (实现下潜)** 权重从 20% 下调至 **19%**。
- 将 **`delivery_closure` (交付收口)** 权重从 20% 下调至 **19%**。

```
collaboration_framing  14%
execution_driving      25%
implementation_depth   19%  (原 20%)
delivery_closure       19%  (原 20%)
adaptive_recovery      10%
agentic_system         13%  (原 11%)
───────────────────────────
总和                   100%
```

### 2.2 `agentic_system` 内部子项权重微调

大幅调高实质性高阶成果（工具 Bonus 与工作流 Bonus）的敏感度权重，同时下调过程类比重：
- `tool_bonus` 权重从 0.08 提高到 **0.12**。
- `workflow_bonus` 权重从 0.08 提高到 **0.12**。
- `structured_rate` 权重从 0.12 下调为 **0.08**。
- `advanced_feature_ratio` 权重从 0.12 下调为 **0.08**。

## 三、协作框定 (Collaboration Framing) 算法升级

### 3.1 纯只读会话不参与 `goal_locking_speed` 平均计算

在 `heuristics.py` 中，对于未检测到任何写工具调用的 session：
- 若 `session.files_modified > 0`：fallback 设为 3（满分 3 轮锁定，对应老数据缺失精细 turns 字段的兼容）。
- 若 `session.files_modified == 0`：`turns_until_first_file_write` **保持为 `None`**（不再强行设为 10）。

在 `scorer.py` 聚合打分中：
```python
locking_speeds = [
    _goal_locking_speed_score(s.turns_until_first_file_write)
    for s in sessions
    if s.turns_until_first_file_write is not None
]
goal_locking_speed = sum(locking_speeds) / len(locking_speeds) if locking_speeds else 100.0
```
- 这确保了只读的排查与架构咨询会话被安全跳过，不扣减锁定速度分数。如果统计周期内全部为只读会话，目标锁定均值默认为 100.0 分。

### 3.2 整合“主动澄清”的容错奖励算法

若用户在第 2/3 轮中积极进行约束探讨（触发了 `active_clarification`），为奖励这一健康的主动对齐行为：
- 该会话在目标锁定打分时，参与计算的轮数 turns 减 1（即 $T = \max(1, T - 1)$）。
- 这使多轮澄清会话（例如 4 轮写入）依然能够以 3 轮锁定的标准获得 100 分，融合了澄清质量与锁定效率。

## 五、多线程冷启动并行解析优化

在 `orchestrator.py` 的编排层中，针对未命中的 placeholder 会话的 ensure_parsed 触发逻辑：
```python
placeholder_sessions = [s for s in sessions if getattr(s, "_is_placeholder", False)]
if placeholder_sessions:
    from concurrent.futures import ThreadPoolExecutor
    with ThreadPoolExecutor(max_workers=8) as executor:
        list(executor.map(lambda s: s.ensure_parsed(cache_for_iter), placeholder_sessions))
```
- 依靠 `ThreadPoolExecutor` 对 logs / SQLite 进行并行并发加载、特征提取与写缓存，极大地降低了由于 schema 版本升级导致缓存全量失效时的冷启动时间。
