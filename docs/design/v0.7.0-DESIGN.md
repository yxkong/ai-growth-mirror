# v0.7.0 详细设计 — Agentic 操作成熟度体系重构

> 本文档是 v0.7.0 的技术设计权威文档，同时是对整个评分体系"从 Prompt 打分器升级为 Agentic 操作成熟度评估"这一战略转型的记录。

---

## 一、问题定义：当前体系的三个核心缺陷

### 1.1 `intent_clarity` 评的是"提示词时代"能力

`intent_clarity` 的原始分由四个子项组成：

```
intent_clarity_raw = constraint_prompt_rate × 0.28
                   + code_context_rate      × 0.24
                   + request_specificity    × 0.26
                   + (context_provision + scope_management)/2 × 0.22
```

**`constraint_prompt_rate` + `code_context_rate` 合计占 52%**，本质上在评「首轮 Prompt 是否写完整了」。

这对 Copilot 型用户（AI = 代码补全器）是合理的：你把需求写清楚，AI 给你补全。
但对 **Agentic 型用户**，这个前提已经失效：

- 高级协作模式是「给方向 → AI 推进 → 用户校正 → 目标锁定」，**多轮澄清本身是能力，不是缺陷**
- `active_clarification_boost`（+8 分上限）是 v0.6.0 的补丁修正，但 `intent_clarity_raw` 的 52% 基盘不变，仍然偏向首轮完备度
- 真正的 Agentic 协作质量（「能否快速给 AI 框定方向并让它自主推进」）在当前五轴中没有独立位置

### 1.2 `agentic_system` 是"门槛触发器"，不是"连续贡献项"

当前代码：
```python
# agentic_system 只在 L4/L5 门禁中使用
if agentic_system >= 88 and execution_driving >= 78 ...:
    score = max(score, 90)  # 触发 L5
elif agentic_system >= 75 and execution_driving >= 70 ...:
    score = max(score, 75)  # 触发 L4
```

这导致：**用户已经开始构建 Skill、Workflow、MCP、Hook、Agent Asset，但这些 Agentic 化能力不能连续地贡献到总分中**。一个真正在构建 AI 工作系统的用户，如果某期交付不稳定，总分可能仍然偏低——评分体系没有识别这是「方法论已成熟，某期执行有波动」。

### 1.3 "恢复推进"被误归为用户问题

当前逻辑：`user_interruptions >= 2` → 生成 `off-track` 摩擦 → 归入 `user-actionable`

但「继续 / 恢复推进 / retry」在 Agentic 场景下大多数情况是：
- 工具链超时
- Agent runtime 上下文中断
- 沙箱环境异常
- 命令执行卡住

这是**环境摩擦**，不是用户能力问题。误归为 `user-actionable` 会错误地压低 `adaptive_recovery`。

## 二、版本目标

### v0.6.x（已部分完成，本版收口）

修复紧急 BUG：`environmental-recovery` 误归类

### v0.7.0（本文档主体）

将 `agentic_system` 升格为**第六个正式评分轴**，同步调整五轴权重，形成"三层成熟度模型"。

### v0.8.0（预留）

将 `intent_clarity` 重命名并重定义为 `collaboration_framing`（协作框定能力），内涵从"首轮完备度"扩展为"多轮协作启动质量"。

### v2.0.0（长期）

评分体系从"单次会话质量评估"演进为"长期 AI 工作系统成熟度评估"。

## 三、三层成熟度模型

```
┌─────────────────────────────────────────────────────────┐
│  第三层：能否沉淀成可复用的 AI 工作系统                    │
│  → agentic_system 轴（v0.7 升格为正式轴）                │
│  → 解决 L4 → L5 跃迁                                    │
├─────────────────────────────────────────────────────────┤
│  第二层：AI 能否被驱动完成真实工作                         │
│  → execution_driving + implementation_depth              │
│  → delivery_closure + adaptive_recovery                  │
│  → 解决 L2/L3 → L4 跃迁（主战场）                        │
├─────────────────────────────────────────────────────────┤
│  第一层：人能否启动协作                                    │
│  → intent_clarity（降权，v0.8 重命名为 collaboration_framing）│
│  → 解决 L1 → L2/L3 跃迁                                 │
└─────────────────────────────────────────────────────────┘
```

## 五、v0.7.0 具体技术设计

### 5.1 `agentic_system` 升格为正式轴

**现有 `agentic_system` 信号（已在代码中计算，直接复用）：**

```python
agentic_system = _bounded_average(
    (skill_usage_session_rate * 100.0,          0.22),
    (workflow_fingerprint_session_rate * 100.0,  0.16),
    (structured_rate * 100.0,                    0.14),
    (advanced_feature_ratio * 100.0,             0.14),
    (soft_threshold(unique_skill_count, 2, 12),  0.10),
    (soft_threshold(workflow_reuse_depth, 1, 8), 0.10),
    (asset_authoring_session_rate * 100.0,       0.06),
    (assetized_session_rate * 100.0,             0.05),
    (inventory_context,                          0.03),
)
```

**改动：** 将其从"门槛触发器"变为正式轴，加入 `total_score` 计算公式，并加入雷达图渲染。

**新 `total_score` 公式：**

```python
total_score = (
    intent_clarity       * 0.15
    + execution_driving  * 0.24
    + implementation_depth * 0.20
    + delivery_closure   * 0.20
    + adaptive_recovery  * 0.11
    + agentic_system     * 0.10
    + tool_leverage_bonus        # max +4，逐步并入 agentic_system
    + workflow_maturity_bonus    # max +3，逐步并入 agentic_system
    + asset_maturity_bonus
    + consistency_modifier
)
```

**L4/L5 门禁条件调整（agentic_system 已进入主分，门禁可适度放宽）：**

```python
# L5 门禁
if (session_count >= 15
    and agentic_system >= 80.0   # 从 88 降到 80（因为已计入主分）
    and execution_driving >= 75.0
    and implementation_depth >= 68.0
    and delivery_closure >= 62.0
    and adaptive_recovery >= 52.0):
    score = max(score, 90)

# L4 门禁
elif (session_count >= 15
    and agentic_system >= 65.0   # 从 75 降到 65
    and execution_driving >= 65.0
    and implementation_depth >= 60.0
    and delivery_closure >= 48.0):
    score = max(score, 75)
```

### 5.2 修复 `environmental-recovery` 误归类

**新增关键词模式（在 heuristic 提取器中）：**

```python
_RECOVERY_CONTINUATION_PATTERNS = frozenset({
    "继续", "恢复推进", "接着来", "接着做", "继续执行",
    "continue", "resume", "retry", "重试", "再跑一次",
    "你卡住了", "卡住了", "没反应", "超时了", "再试一次",
    "keep going", "go on", "proceed",
})
```

**归因规则：**

```python
# 在 friction 分类时，匹配 recovery continuation pattern 的消息
# 归为 "environmental-recovery"，不生成 off-track，不归入 user-actionable
if _is_recovery_continuation(user_message):
    friction_type = "environmental-recovery"
    attribution = "environmental"   # 不计入 user_actionable_ratio
    # 正向信号：记录 recovery_continuation_count
```

**`recovery_continuation_count` 作为正向信号加入 `adaptive_recovery` 子项：**

```python
# 有效恢复后（恢复后 N 步内有文件变更或验证行为）归为正向
recovery_success_rate = successful_recoveries / max(recovery_continuation_count, 1)
```

### 5.3 雷达图升级为六轴

**报告层改动：**
- `radar_axes` 从 5 个扩展为 6 个，加入 `agentic_system`
- 雷达图 SVG 多边形从五边形改为六边形
- tooltip 展示 `agentic_system` 的子维度分解
- `gap_rankings` 优先级逻辑更新：`agentic_system` 短板优先级高于 `intent_clarity`（因为 Agentic 系统化能力对 L4→L5 更关键）

**i18n 更新（zh/en）：**

```yaml
# view_model_zh.yaml
agentic_system:
  label: "Agentic 系统化"
  tooltip: "轴分 {score} · skill 使用率 {skill_usage_pct}% · workflow 结构化 {structured_pct}% · 资产创作 {asset_authoring_pct}%"
  gap_reason: "Agentic 系统化能力偏弱：尝试用 skill/workflow/MCP 沉淀可复用协作方法"
```

### 5.4 intent_clarity 权重调整（v0.7.0 执行）

只改权重系数，不改内部计算逻辑（内部重新定义留给 v0.8.0）：

```python
# 调整前
total_score = intent_clarity * 0.20 + execution_driving * 0.22 + ...

# 调整后
total_score = intent_clarity * 0.15 + execution_driving * 0.24 + ...
```

## 六、v0.8.0 预留设计：`collaboration_framing`

> 本节为预留设计，v0.8.0 实施，不在 v0.7.0 代码中动。

### 重命名

```
intent_clarity  →  collaboration_framing
（任务表达）     →  （协作框定能力）
```

### 重新定义子项（"首轮完备度" → "协作启动质量"）

| 旧子项 | 权重 | 新子项 | 权重 | 变化说明 |
|---|---|---|---|---|
| `constraint_prompt_rate` | 0.28 | `direction_clarity_rate` | 0.20 | 方向性而非约束完备性 |
| `code_context_rate` | 0.24 | `context_grounding_rate` | 0.18 | 不限首轮，任何轮次附上下文都算 |
| `request_specificity` | 0.26 | `goal_locking_speed` | 0.28 | N 轮内锁定目标的速度（新信号） |
| `context+scope` avg | 0.22 | `active_clarification_rate` | 0.34 | 主动澄清从补丁变核心信号 |

### `goal_locking_speed` 新信号定义

```python
# 目标锁定速度：用户在前期让 AI 锁定目标、边界与可交付产出路径的速度
# 工程会话用首次文件写入作为可观测代理；快（<=3 轮）→ 满分；慢（>10 轮仍无明确产出路径）→ 低分；中间线性插值
goal_locking_speed = soft_threshold(
    turns_until_first_file_write,
    lo=10,   # 10 轮才开始写代码 → 0 分
    hi=3,    # 3 轮就开始写代码 → 满分
    max_pts=100,
    inverted=True,  # 轮数越少，得分越高
)
```

## 七、架构硬约束（继承自 v0.6.0 + 新增）

1. **单源权重原则**：权重系数只在 `scorer._compute_growth_level` 中定义，`ARCHITECTURE_PRINCIPLES.md` 和报告 i18n 均从代码注释生成，不得另起真源。

2. **`agentic_system` 信号不重复统计**：升格为正式轴后，`tool_leverage_bonus` 和 `workflow_maturity_bonus` 中与 `agentic_system` 重叠的信号逐步剥离，v0.7.0 先共存（bonus 继续存在），v0.8.0 完成合并。

3. **`environmental-recovery` 过滤前置**：必须在 friction 归因阶段就完成过滤，不得在 scorer 层再做二次校正。

4. **雷达图六轴向后兼容**：旧快照（五轴）加载时，`agentic_system` 显示"—"（无数据），不报错，不强制重算。

5. **L1-L5 等级边界冻结**：权重调整不得影响等级边界（0/38/56/75/90），边界调整需单独提案。

## 八、报告内容闭环设计

> **闭环原则**：每项评分体系变更必须在报告中有可感知的用户侧呈现，不能停留在后端指标调整。

### 8.1 v0.7.0 报告新增/变化内容

| 报告区域 | 变化 | 用户能看到什么 |
|---------|------|--------------|
| **雷达图** | 五边形 → 六边形 | 新增第六轴「Agentic 系统化」，展示 skill/workflow/MCP 使用分布 |
| **轴 tooltip** | agentic_system 新增 | hover 时显示：skill 使用率、workflow 结构化占比、资产创作率 |
| **gap_rankings** | 优先级更新 | `agentic_system` 短板排在 `intent_clarity` 前面（更影响 L4→L5）|
| **adaptive_recovery 说明** | environmental-recovery 剔除 | 「继续/重试」类消息不再出现在用户侧摩擦列表 |
| **分数卡** | 权重透明展示 | 各轴权重百分比更新（15/24/20/20/11/10）|

### 8.2 与 v0.6.0 报告的差异对比

```
v0.6.0 报告                           v0.7.0 报告
──────────────────────────────────    ──────────────────────────────────
五边形雷达 (5 轴)                →     六边形雷达 (6 轴，加 agentic_system)
intent_clarity 20%               →     intent_clarity 15%
agentic_system 不在雷达图        →     agentic_system 独立轴，有 tooltip
"继续" 可能出现在摩擦列表         →     "继续/重试" 归入 environmental，不展示
```

### 8.3 backward-compatible 渲染规则

旧快照（v0.6 五轴）加载到 v0.7 报告时：
- `agentic_system` 轴显示 `—`（无历史数据），不显示 0 分
- 雷达图仍按六边形渲染，但第六轴标注「暂无数据」
- 环比 delta 卡片：新增轴首期不显示 delta，只显示本期值
