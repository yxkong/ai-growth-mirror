# v1.0.0 有效任务契约与 Agentic 报告校准

English version: [v1.0.0-DESIGN.md](../en/design/v1.0.0-DESIGN.md)

## 目标

v1.0.0 用于修正通用 Agentic 报告在高规则化用户身上的三个失真点。本版本将产品版本与缓存 schema 统一从 `1.0` 重新起线；后续不改变 schema 的迭代只 bump patch 版本。

1. 把“读代码侦察”误判为目标锁定慢。
2. 把 `build`、`compile`、`.ps1`、`.bat` 等工程验证漏判为没有测试。
3. 把 Skill / Rule / Workflow 中已经存在的任务契约，误判为用户首轮没有写验收。

## 执行计划

### P0：模型补齐

- `SessionRecord` 增加任务契约来源、契约履约、写前只读侦察计数。
- cache schema 统一从 `1.0` 起线，避免混用。

### P1：reader 证据采集

- Cursor transcript 记录首次写入前的 read / non-read tool 数量。
- Gemini / Antigravity reader 支持 UTF-8、UTF-8-SIG、GBK fallback。
- Gemini / Antigravity reader 记录写前侦察与自定义验证命令。

### P2：启发式与评分校准

- 扩展验证命令识别：采用关键词/脚本后缀匹配，而非枚举完整命令；测试、构建、编译、常见 Windows 脚本都进入 Proof Loop。
- 新增 `effective_contract_rate`，统一纳入显式 Prompt、Skill/Rule、Agent 派生契约。
- 协作框定轴使用“有效任务契约”修正纯首轮 Prompt 偏见。
- 交付收口轴使用“契约履约率”修正只看测试命令的偏见。
- 首次写入前如果全部为只读侦察，不再按普通延迟惩罚目标锁定速度。

### P3：报告与训练建议

- `ai-growth-mirror.summary.json` 增加 `scorecard.task_contract` 稳定摘要。
- growth plan 区分“用户没写验收”和“已有契约但 Agent 未履约”。
- 对已有 Skill / Rule 契约的用户，建议重点转向 Agent 契约复述与收口合规。
- 「你在做什么」跨会话主题由 `work_focus/` LLM 综合生成；无 LLM 或失败时回退规则护栏；`goal_mix` / 工具 / 语言统计仍由规则汇总。
- Prompt Coach / growth_coach / prompt_lens 去除固定训练模板与 canned 建议，个性化结论由 LLM 基于证据生成；i18n 仅保留标签与结构模板。

### P4：验证

- 覆盖启发式：构建命令识别、Skill 契约识别、后置纠偏识别。
- 覆盖 Gemini / Antigravity：GBK transcript、写前只读侦察、构建验证。
- 覆盖报告链：summary task contract 输出、只读侦察不惩罚 goal locking。
- 覆盖版本一致性：pyproject、`__init__`、README badge、uv.lock。

## 版本策略

- `CACHE_SCHEMA_VERSION=1.0` 对应产品版本线 `v1.0.x`。
- schema 不变时，只允许 patch 迭代，例如 `v1.0.1`、`v1.0.2`。
- schema 升级时，产品版本线同步升级，例如 `CACHE_SCHEMA_VERSION=1.1` 对应 `v1.1.0`。
- 每次升版必须联动 `pyproject.toml`、`ai_growth_mirror/__init__.py`、`uv.lock`、`README.md`、`docs/design/README.md`、`docs/design/PRODUCT_ROADMAP.md` 和当期设计文档。

## PowerShell 命令规则

- Windows 下 checkpoint、版本读取和测试命令必须写成纯 `pwsh` 形式，不使用 Bash heredoc。
- 在 `pwsh -Command` 字符串里需要 `$` 变量时，必须使用反引号转义，例如 `` `$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD ``。
- 复杂脚本优先落成临时 `.ps1` 或 Python 脚本；不要把多层 `$变量`、管道和复杂正则塞进一条双引号 command。
- 搜索多个固定关键字时，优先使用 `rg --fixed-strings -e ...`，避免 `|` 被 shell 或正则层误解。

## 验收标准

- v1.0.0 能解释“为什么用户没有首轮手写验收，但仍可能有有效任务契约”。
- 报告能展示任务契约来源分布与履约率。
- Antigravity / Gemini 的构建验证和 Windows 脚本不再被漏判。
- 只读侦察不再拉低目标锁定速度。
- 聚焦单测全部通过。
