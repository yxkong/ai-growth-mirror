# v0.8.0 详细设计 — collaboration_framing 重定义与 goal_locking_speed 信号引入

> 本文档是 v0.8.0 的技术设计权威文档，定义了协作框定能力（Collaboration Framing）的全新四维结构，以及首个基于时序的协作效率指标（Goal Locking Speed）的提取与打分逻辑。

---

## 一、设计背景与核心目标

在之前的版本中，用户启动协作的评价轴为 `intent_clarity`（任务表达）。这在 Prompt 时代是极为合理的。但在 **Agentic 时代**：
1. **多轮澄清不应被低分惩罚**：协作的首要能力不是在首轮写出完美 Prompt，而是通过交互快速锁定目标（Goal Locking）。
2. **需要一个代表“目标锁定速度”的显式信号**：衡量从对话开始到 AI 产生第一次有效修改（如 Write/Edit 写入操作）所经历的对话轮数。
3. **消除评分系统中的“外挂加分项”**：原本的 `tool_leverage_bonus` 与 `workflow_maturity_bonus` 在主分外独立加分，导致主轴分值失真。本版将它们彻底合并至 `agentic_system` 轴，实现主轴分值的一体化。

---

## 二、架构演进与指标重定义

### 2.1 评分轴重命名

将第一层能力轴从 **`intent_clarity`（任务表达）** 重命名为 **`collaboration_framing`（协作框定）**。

### 2.2 六轴权重调整

```
collaboration_framing  14%  （原 intent_clarity，15%）
execution_driving      25%  （原 24%）
implementation_depth   20%
delivery_closure       20%
adaptive_recovery      10%  （原 11%）
agentic_system         11%  （原 10%）
───────────────────────────
总和                   100%
```

同时，`total_score` 公式移除了 `tool_leverage_bonus` 和 `workflow_maturity_bonus` 的外挂加成。

## 三、协作框定（Collaboration Framing）全新四维子项设计

```
collaboration_framing = _bounded_average(
    (direction_clarity_rate     * 100.0, 0.20),
    (context_grounding_rate     * 100.0, 0.18),
    (goal_locking_speed,                 0.28),
    (active_clarification_rate  * 100.0, 0.34)
)
```

| 子项名称 | 权重 | 来源与物理含义 |
| :--- | :--- | :--- |
| `direction_clarity_rate` | 0.20 | 即原 `constraint_prompt_rate`（方向与约束清晰度） |
| `context_grounding_rate` | 0.18 | 即原 `code_context_rate`（上下文注入率） |
| `goal_locking_speed` | 0.28 | **【新增】** 用户驱策 AI 在前期锁定目标、边界与可交付产出路径的速度；工程会话由 `turns_until_first_file_write` 作为可观测代理，各 session 得分取均值 |
| `active_clarification_rate` | 0.34 | 主动澄清率（由 `active_clarification` 直接驱动，从 v0.6 补丁加分改为正式子项） |

### 3.1 `goal_locking_speed` 信号定义与打分逻辑

对于单个 session，定义首轮有效写入前所经过的用户消息轮数为 $T = \text{turns\_until\_first\_file\_write}$。
线性插值公式：
$$
\text{locking\_score}(T) = \begin{cases}
100.0, & T \le 3 \\
0.0, & T \ge 10 \\
100.0 \times \frac{10 - T}{10 - 3}, & 3 < T < 10
\end{cases}
$$
在聚合模块 `aggregate` 中，将所有有效 session 的 $\text{locking\_score}(T)$ 取算术平均值，得到轴评分参数 `goal_locking_speed`。

### 3.2 信号提取与 fallback 设计

对于能够进行细粒度 Tool 级别解析的 reader（如 `claude_code`, `cline`, `cursor` jsonl, `gemini` jsonl）：
- 当遍历对话流时，用户发出第 $N$ 个 human message。
- 当 AI 在该轮的回复中，首次调用属于 `WRITE_TOOL_NAMES` 的写/编辑文件工具时，记录 $\text{turns\_until\_first\_file\_write} = N$。
- 对未检测到任何写工具调用的 session（无精细工具流的简易/历史会话），后置处理模块（`enrich_agentic_signals`）自动检测：
  - 若 `session.files_modified > 0`：fallback 设为 3（满分，3 轮锁定）。
  - 若 `session.files_modified == 0`：fallback 设为 10（0 分，10 轮未锁定）。

## 四、外挂 Bonus 合并至 `agentic_system` 轴

移除 `total_score` 公式中的 `tool_leverage_bonus` 和 `workflow_maturity_bonus` 外挂加分，将它们并入 `agentic_system` 的 `_bounded_average` 算式中：

```python
agentic_system = _bounded_average(
    (skill_usage_session_rate * 100.0, 0.18),
    (workflow_fingerprint_session_rate * 100.0, 0.14),
    (structured_rate * 100.0, 0.12),
    (advanced_feature_ratio * 100.0, 0.12),
    (_soft_threshold(float(unique_skill_count), 2.0, 12.0, 100.0), 0.08),
    (_soft_threshold(float(workflow_reuse_depth), 1.0, 8.0, 100.0), 0.08),
    (asset_authoring_session_rate * 100.0, 0.05),
    (assetized_session_rate * 100.0, 0.04),
    (inventory_context, 0.03),
    (tool_bonus, 0.08),       # 融入原 tool_leverage_bonus 微观指标
    (workflow_bonus, 0.08),   # 融入原 workflow_maturity_bonus 微观指标
)
```

## 五、向后兼容设计

为了让旧的 `v0.6.0` 和 `v0.7.0` 快照数据在 `v0.8.0` 报告及快照对比页面中无缝运行，采用如下规则：
1. **数据反序列化兼容**：在 `SnapshotSource.from_dict` 和 `compare_snapshot_sources` 中，如果读取到的历史快照包含 `intent_clarity` 字段而缺失 `collaboration_framing` 字段，则自动重命名并映射至 `collaboration_framing`。
2. **快照缓存隔离与重新解析**：由于引入了 `turns_until_first_file_write`，将 `CACHE_SCHEMA_VERSION` 升级至 `"1.4"`。旧缓存将由于版本不匹配被自动废弃并自动重新解析，从而使全部 session 记录均能被赋予正确的 v0.8.0 时序字段。
