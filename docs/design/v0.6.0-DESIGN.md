# v0.6.0 详细设计 — 训练环比增量闭环（Practice Feedback Loop）

> 版本目标、任务拆解、架构约束与验证计划权威文档。实现阶段以此为准。

---

## 1. 问题定义

### 1.1 训练建议的「消失黑洞」

v0.5.0 及以前，每次生成报告都会输出 2 条 Action Contract 训练建议。但建议给出后：

- 下一期报告**无法判断**用户是否执行了上一期建议
- 用户**感受不到进步**，因为报告每次都在诊断当前期，缺乏纵向闭环
- 系统无法区分"建议被忽略"还是"建议已执行但场景不足"

**根因**：报告生成是无状态的单期行为，snapshot 仅作归档，未参与本期报告的训练判定逻辑。

### 1.2 「多轮交互」评分悖论

当前 `intent_clarity` 轴的计算依赖：

| 子指标 | 权重 | 信号来源 |
|--------|------|----------|
| `constraint_prompt_rate` | 28% | 首轮是否带约束 |
| `code_context_rate` | 24% | 是否包含代码上下文 |
| `request_specificity` | 26% | 需求是否具体明确 |
| `context_provision` | 11% | 是否提供相关背景 |
| `scope_management` | 11% | 范围是否收口明确 |

**问题**：当用户通过 2–3 轮交互（逐步澄清目标→追加约束→确认范围）完成一个完整高质量任务时，`constraint_prompt_rate` 因首轮无约束而被惩罚，尽管最终该会话的交付质量非常高。

**设计决策**：v0.6.0 引入「主动澄清加分」信号——识别"用户主动追问→AI 据此补全上下文"的会话模式，将其判定为**高阶协作意图的显式信号**，而非首轮约束缺失的惩罚项。

## 3. 评分修正：主动澄清信号（G-3）

### 3.1 什么是主动澄清

会话中出现以下模式时，判定为「主动澄清（Active Clarification）」：

```
用户轮次 1：任务描述（可以不含约束）
AI 轮次 1：提问或建议澄清方向
用户轮次 2：明确追加约束 / 范围 / 验收条件（新增 context 而非重复）
→ 该会话标记为 active_clarification = True
```

判定规则（已落地实现，`domain/session/heuristics.detect_active_clarification`，heuristic 与 LLM 两路共用同一规则）：
- 用户轮次 `user_message_count ≥ 3`
- 用户的第 2–3 轮（`top_user_messages[1:3]`）包含约束词（`CONSTRAINT_WORDS`：`不要 / must not / ensure / make sure / avoid / without` 等）

> 说明：早期设计草案曾要求叠加「首轮 `request_specificity < 70`」与「`delivery_closure ≥ 60`」双门槛，但为保证 heuristic 模式下零 LLM 依赖、规则稳定可解释，实现收敛为「轮次 + 后续轮约束词」两条；置信度由聚合层样本量统一降级处理。

### 3.2 评分修正规则

修正在 `domain/growth/scorer.py` 的 `intent_clarity` 计算中加入（单源函数 `_intent_clarity_boost`）：

```python
INTENT_CLARITY_BOOST_CAP = 8.0
_ACTIVE_CLARIFICATION_FULL_BOOST_RATE = 0.20

def _intent_clarity_boost(active_clarification_rate: float) -> float:
    if active_clarification_rate <= 0.0:
        return 0.0
    ramp = (active_clarification_rate / 0.20) * 8.0
    return round(min(8.0, ramp), 1)

intent_clarity = min(100.0, intent_clarity_raw + _intent_clarity_boost(rate))
```

**设计理由**：
- 线性 ramp，在主动澄清率达到 20% 时触达 +8 上限，低于 20% 按比例给分（如 10% → +4），既奖励高阶协作又不至于偶发会话刷满。
- 上限 +8 分，不允许仅靠澄清行为绕过其他维度直接拉满。
- 加成值由 `_intent_clarity_boost` 单源计算，评分与报告「透明展示」读取同一函数，杜绝公式漂移。

### 3.3 展示规则

- 报告中显示「主动澄清率」指标（`active_clarification_rate`）
- 当 boost > 0 时，`intent_clarity` 轴的 tooltip 补充说明："含 +N 分主动澄清加成"
- 加分逻辑在阶段评估区块透明展示，不隐藏

## 4. Action Contract 追踪（G-1）

### 4.1 追踪机制

上一期 snapshot 的 `sidecar.growth_plan` 包含 `action_contracts[]`，每项有：
- `axis`：对应五轴名（如 `intent_clarity`）
- `contract_type`：`rule | skill | workflow | template`
- `target_behavior`：期望改善的具体行为描述

本期生成时，从 `infra/snapshots.py` 读取最近一份 snapshot 的 `action_contracts`，在 `application/growth_trajectory.py` 中执行**改善效果评估**：

```python
def evaluate_contract_outcomes(
    prev_contracts: list[ActionContract],
    current_profile: GrowthProfile,
    prev_profile: GrowthProfile,
) -> list[ContractOutcome]:
    ...
```

### 4.2 改善效果判定逻辑

| 判定结果 | 条件 | 展示 |
|----------|------|------|
| `improved` | 目标轴得分提升 ≥ 5 分 | ✅ 本期改善 |
| `partial` | 目标轴得分提升 1–4 分 | 🔄 部分改善 |
| `unchanged` | 目标轴得分变化 < ±3 分 | ➖ 无明显变化 |
| `no_data` | 首次生成，无上期合约 | 灰色，"暂无前序数据" |
| `schema_mismatch` | 上期使用旧轴名 | ⚠️ 历史模型不兼容 |

**置信度修正**：

当 `prev_session_count < 8` 或 `current_session_count < 8` 时，所有判定结果的 `confidence` 降为 `low`，报告中标注"样本量不足，结论仅供参考"。

### 4.3 sidecar schema 新增字段

`summary.json` 的 `growth_trajectory` 下新增：

```json
{
  "contract_outcomes": [
    {
      "axis": "intent_clarity",
      "result": "improved",
      "delta_score": 8,
      "confidence": "medium",
      "prev_contract_text": "每次任务首轮带上验收条件",
      "evidence": ["本期 constraint_prompt_rate 提升 12%"]
    }
  ]
}
```

## 5. 环比增量分析（G-2）

### 5.1 数据来源

- 仅读取本地 `ai-growth-mirror-archive/index.json`，无网络依赖
- 若 `archive` 中历史条目 = 0：环比分部整体隐藏，显示"暂无前序数据"
- 若 ≥ 1 条：读取最近一份作为 `prev_snapshot`

### 5.2 delta 计算（`domain/snapshots/comparison.py` 新增）

新增 `compute_axis_delta()` 纯函数：

```python
@dataclass
class AxisDelta:
    axis: str
    current_score: float
    prev_score: float
    delta: float
    trend: Literal["improving", "declining", "flat"]
    confidence: Literal["high", "medium", "low"]
```

趋势判定规则：
- `|delta| < 3`：`flat`
- `delta >= 3`：`improving`
- `delta <= -3`：`declining`
- 当任意一期样本 `< 8` 时：`confidence = low`

### 5.3 `human_intervention_rate` 趋势

新增字段追踪 `human_intervention_session_rate` 的环比变化，纳入 `TrendSummary`：

```python
@dataclass
class TrendSummary:
    ...
    intervention_rate_delta: float  # 正值=恶化（人工介入更多）
    intervention_trend: Literal["improving", "declining", "flat"]
```

## 6. 报告内环比卡片（G-5）

### 6.1 位置与触发条件

- 位置：`#section-growth-delta` 区块内，雷达图下方
- 触发：`growth_trajectory.available = True`（有历史 snapshot）
- 无历史时：整个 delta 卡片区域不渲染（不显示空框）

### 6.2 SVG 趋势折线

在 `report.html.j2` 中使用纯 SVG 实现，约束：
- 宽度自适应容器（`viewBox="0 0 300 80"`）
- 最多展示 10 个点，超出时取最近 10 个
- 折线颜色：improving=`var(--color-success)`，declining=`var(--color-error)`，flat=`var(--color-muted)`
- 点位 tooltip（与现有雷达图 tooltip 复用同一逻辑）

### 6.3 变化箭头卡片

每轴一个小卡片，包含：
- 轴名 + 当前分 + delta（`+8` / `-3` / `±0`）
- 方向箭头（↑ ↓ →，使用 SVG path 而非 Unicode 确保跨平台一致）
- 置信度徽章（`low confidence` 时显示灰色，配置文案"样本不足"）

### 6.4 Action Contract 回看区

在 `#section-growth-plan` 下方新增折叠区块（`<details>`）：
- 标题："上期训练回看"
- 内容：`contract_outcomes` 列表，按 `improved > partial > unchanged` 排序
- 无前序数据时：折叠区块内显示"首次生成，暂无训练回看数据"而非隐藏整个 details

## 7. CLI `status` 命令（G-4）

### 7.1 命令签名

```bash
ai-growth-mirror status [--config <path>]
```

### 7.2 输出格式（纯文本，无 LLM 调用）

```
📊 AI Growth Mirror — 当前状态
──────────────────────────────────────
上次生成：2026-06-05 14:32（3 天前）
等级：L3 · 协作指数：72

样本进度
  本周新增会话：12 / 建议最低 15
  ████████░░ 80% → 再积累 3 个有效会话可生成新报告

本周练习提示（来自上期 Action Contract）
  › 下一个任务首轮加入验收条件（Acceptance Criteria）
  › 尝试用 "@workspace" 提供代码上下文后再提需求

运行 `ai-growth-mirror generate` 生成新报告
```

### 7.3 技术约束

- 响应时间 < 100ms：**禁止**触发完整 snapshot 重算
- 仅读取：`archive/index.json`（最新一条）+ 本地缓存 manifest
- 样本计数：仅统计本机缓存中近 7 天内 `session_date` 的记录数，不做 LLM 提取
- 本周练习提示：直接读 `latest_snapshot.growth_plan.action_contracts[0:2]` 的 `target_behavior` 字段
- 无历史 snapshot 时：简化输出"尚未生成过报告，运行 generate 开始"

### 7.4 实现位置

```
cli.py            # 新增 `status` 子命令
application/
  status_view.py  # StatusView DTO（新增文件）
infra/
  snapshots.py    # 新增 load_latest_snapshot_meta()（只读 index.json，不加载全量）
```

## 8. 架构约束与分层（继承 v0.5.x L5 护栏）

### 8.1 分层归属

| 新增能力 | 分层位置 | 说明 |
|----------|----------|------|
| `active_clarification` 信号检测 | `infra/extractors/heuristic.py` | 规则层检测，不触发 LLM |
| `active_clarification_rate` 聚合 | `domain/growth/scorer.py` | 纯计算，无 I/O |
| `intent_clarity_boost` 修正 | `domain/growth/scorer.py` | 同上 |
| `AxisDelta` / `ContractOutcome` DTO | `domain/snapshots/comparison.py` | 纯数据结构 + 纯计算 |
| `compute_axis_delta()` | `domain/snapshots/comparison.py` | 纯函数 |
| `evaluate_contract_outcomes()` | `application/growth_trajectory.py` | 组装层，读 profile |
| `load_latest_snapshot_meta()` | `infra/snapshots.py` | 仅读 index.json |
| `StatusView` DTO | `application/status_view.py` | 新增文件 |
| `status` 子命令 | `cli.py` | Adapter 层 |
| SVG 趋势折线 + 变化箭头 | `assets/templates/report.html.j2` | 展示层，无业务逻辑 |
| 上期训练回看区 | `assets/templates/report.html.j2` | 展示层，`<details>` 折叠 |

### 8.2 L5 护栏（继承 v0.5.x）

- **localStorage 降级**：主题读取带 `try-catch`，`file://` 沙箱下静默降级到系统偏好
- **防御性 JSON 解析**：`#report-data` 解析全部带 `try-catch`；字段缺失时局部降级，不全局崩溃
- **首帧主题无闪烁**：`<head>` 内同步脚本读取 `localStorage` → 在 `<html>` 打 `data-theme` 属性
- **零外部依赖**：新增 SVG 折线禁止引入 D3/Chart.js；`status` 命令禁止网络调用
- **`file://` 双击可运行**：所有新增前端逻辑必须在 `file://` 协议下测试通过

### 8.3 缓存 Schema 版本

- 新增 `active_clarification` 字段到 `SessionRead` → `SESSION_READ_SCHEMA_VERSION` 升至 `"1.3"`
- 旧缓存（1.1 / 1.2）自动失效，触发重新提取（heuristic 模式下无 LLM 成本）
